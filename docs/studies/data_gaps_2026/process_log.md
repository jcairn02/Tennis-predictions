## 8. Weak points

* **Threats to validity, most important first:**
  * **Resolution.** The harm check's half-width (0.14 mLL) is far wider than a repair's plausible effect. It rules out only a large harm, which is what it is for. It is not evidence of a gain.
  * **The control arm.** The control was the 10 Oct instance, built with older chain code. The gate shows the code changes move nothing on the 60,412 unreachable matches, but a change touching only late-2026 rows would not show there (judgment call 5).
  * **Identity errors.** H1 found about 4% wrong player links in TennisLive's name routes, and WTA-id splits. The first touch few matches in the scope; the second are fixed for the weekly runs. Weekly snapshots are screened by rule, not by hand.
  * **Box-score comparability** rests on overlap measurements, except for the ITF API, which had no overlap: there it is an assumption.
  * **Leakage.** The additions are timed by the builder's cautious windows. The layer's season-wide re-centring is a formal look-ahead (judgment call 8; about 1e-6 on the inputs).
  * **Repeated looks.** The harm check was read once. The coverage counts (outcome-free) were read several times while the alarm's baselines were being fixed.
* **Where a flaw would most likely hide:**
  * in the identity resolution of the 29,600 women's ITF-qualifying results (results only, mostly resolved through crosswalks);
  * in the weekly automation, where a source's format change could pass every check with degraded content. The alarm counts matches; it does not judge their quality.
* **What a re-design would do:**
  * build a fresh control with today's code beside the feed arm;
  * hand-check samples drawn from the scope only;
  * measure the ITF API against a trusted record;
  * hold the layer's shift per build.
* **The experiment most likely to overturn the conclusion:** score the feed arm on the 2027 season, out of sample.
