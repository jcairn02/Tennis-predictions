## 8. Weak points

* **The trial's events were chosen by hand,** one per stratum, before any request; all five turned out to be events without speeds. The checks of speeds therefore rest on the bulk's first Masters event so far.
* **The empty-file threshold** (`EMPTY_BYTES` = 200) is set from one kind of empty answer (88 bytes). An empty document of another shape over 200 bytes would count as data and keep a route open; it would cost requests, not data.
* **Court Vision's give-up after 3** could miss tracking at an event whose final and semi-finals were played off the tracked courts. The backfill's 4 events and the trial's 5 do not show such a case.
* **The API-only fallback** asks the API only for codes whose static copy is missing; a static copy that exists but is in the older format is kept as it is (judgment call 2).
* **The daily collector's held files** are trusted as complete when its own staging marks the match complete; a file it fetched later and overwrote is not re-checked here.
* **Where a flaw would most likely hide:** the orientation of the key statistics' players against MatchBeats' (check C assumes they are the same order; the staging records both, and B orients by the key statistics' own players).
* **Added 27 Oct 2026:**
  * **The plan is ManTennisData's list.** A match it lacks, or lists without a stats link (1,078 rows in the 26 Oct copy; the 2015-21 backfill found such rows mostly walkovers, not checked for 2025-26), was never asked; matches after 18 Oct 2026 are not in it.
  * **A rerun after a later ManTennisData refresh changes the denominators** (25,593 codes on the 26 Oct copy). The report's numbers are for the 19 Oct copy.
  * **The map's before/after** (545 -> 4,303 at shot level) mixes this source with others' changes between 16 and 27 Oct; the attributed numbers (4,292 of 4,303; 625) are the ones to quote.
  * **The checks reuse the backfill's code** (`src/eda/infosys_atp_backfill/checks.py`) by pointing its module path at these tables. A change to that module changes these checks too.
  * **The 18 failing answers** (17 HTTP 500 from the API routes, 1 HTTP 400) were asked twice and are counted as errors, not absences; a third run would ask them again.
* **Added 27 Oct 2026, the owner's decisions:**
  * **Which ending is right is not decided here.** The tables keep the older copy's ending (the one the rally analysis and the box-score checks agree with) and the newer one beside it (`result_newer`). A study that uses endings should read both.
  * **The reminder needs the daily task to run.** Weeks with the PC off send nothing; an unreadable calendar falls back to 28 Dec.
  * **"Done" means a full run after the due date was staged, not that the map was rebuilt.** The reminder stops before the procedure's last step; the session that runs the top-up must rebuild the map.
* **Added 28 Oct 2026, after the pass:**
  * **The 24 Oct evidence files were overwritten by the restaging** (the wrapper rewrites them by design): `infosys_atp_recent_checks.json`, the mismatch file, the stage summary, `infosys_atp_recent_summary.json` and `infosys_atp_recent_events.csv` now describe the 28 Oct state on ManTennisData's 26 Oct copy.   * **The arbiters of the endings are not independent of the site.** SirGenkii's copy is the same site's files saved earlier; the key statistics are the site's own. Where the older copy is right in a way neither shows, or both are wrong together, nothing here would catch it.
