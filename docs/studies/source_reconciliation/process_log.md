# Duplicate sources: which is most accurate, and can they be combined: process log

## 1. The request

* **The owner's words, verbatim** (16 Oct 2026):
  > "For a lot of our data, we have multiple sources, some of those sources differ.
  > We currently have sources that supply our main model and other sources are frozen out that duplicate in function.
  >
  > Do an analysis on where we have duplicate data THAT CAN POTENTIALLY DIFFER, see if we are using the most accurate source on average, and see if some sort of average or blend (or fixing corrupt data) can be built that uses a combination of these sources."
* **How it was read (the interpretation acted on):**
  * "Our main model" = the current best model (the template of the 8 Oct decision, as amended: 57 inputs, the serve-speed stage, the five-pattern stage). The analysis covers the raw fields those inputs are built from. Fields no input reads are listed in the inventory but not analysed.
  * "Duplicate data that can potentially differ" = a field of the same match (or player) held by two or more sources, where the values are not copies of one another by construction. A derived copy (Open Tennis Data, built from tennis-data and Sackmann) is listed as dependent and not counted as independent evidence.
  * "Frozen out" = sources on disk that Stage 0 / Stage 1 do not read for that field (the official WTA box scores, the ATP's Infosys files, TDI, ManTennisData, SofaScore, TennisLive, the other books ...), whether by precedence or by the frozen-reference rule.
  * "The most accurate source on average" needs a referee per field. Fixed before any comparison:
    * box scores: an independent point-by-point record of the same match, recounted, where it holds every point and agrees with the score; then the accounting identities with the score; then agreement among the other sources;
    * results, scores, context (surface, indoor, level, round, dates): the official record where held, else the majority of independent sources;
    * birth dates: the tours' own records, else the majority;
    * closing odds: log loss against results (the only outcome-based reading in the study);
    * serve speed: the point-level mean of the same match (the most direct measurement).
  * "Average or blend" = for continuous fields (odds, speed), a weighted combination; for discrete counts, a consensus that picks one source's whole box per match. The 6 Oct review's rule stands: counts are never mixed inside a match ("Mixing sources inside a match creates ratios no source recorded", data-continuity § 4.5).
  * "Fixing corrupt data" = rows where the model's source is contradicted by a complete recount and by at least one other independent source, with a unique replacement; proposed as correction tables, not applied (adopting is the owner's call; main-tour corrections are repairs decided on the data evidence, with the frozen-reference harm check).
* **Other readings, set aside:**
  * *Every field of every dataset, model or not.* Set aside: the owner frames it as the sources that "supply our main model"; fields no input reads are listed only.
  * *Re-open settled comparisons* (the Slam box scores of 6 and 9 Oct; Pinnacle against the books' blends at the close, odds-sources § 4). Not redone; summarised with their records. The one odds question still open is the stand-in where Pinnacle is missing (August 2025 on).
  * *Average box-score counts across sources.* Set aside for the reason above.
* **Questions put to the owner:** none so far. The scope and referees are conventional readings of the request; logged here so they can be corrected.
* **The target** (adoption framework § 1): data accuracy, not a betting price. The only outcome-based reading (odds) scores closing prices against results on matches played before 29 Jul 2026. Matches from 29 Jul 2026 are the proposed sealed holdout of the feature-provenance study (not decided, but every study since has left their results unread), so no outcome of theirs is read. Fixed before any result was read.

## 3. Plan

*As first written, 16 Oct 2026 13:52 PDT, before any comparison was run.*

**Part A: the inventory.** For each raw field the model reads, every source on disk that holds it for the same matches, the one the model uses (and the precedence rule), whether the copies are independent, and the overlap with Stage 0's matches (link files and staged tables). Output `inventory.csv` and the README's map.

**Part B: box scores** (they feed about 41 of the 57 inputs).
* B1, referees by recount: per-player nine counts recounted from independent point records where they hold every point and agree with the score: the WTA's umpire event log (WTA tour, Apr 2019 – 2026), the ATP's Infosys MatchBeats (2018–2025: the decrypted backfill, the Challengers, SirGenkii), TDI's points (2026), SofaScore's points (the counts that need no serve number), the Match Charting Project. The Slam feeds serve as a positive control (the recount must reproduce the decided overrides).
* B2, each box source against each referee, count by count, by tour, level and season: Stage 0 as built; Sackmann raw; TML raw; the WTA API's box; the Infosys key statistics (handoff, backfill, SirGenkii, daily); ManTennisData; TDI's statistics; SofaScore's box; the ATP-site scrape (atp_scraped_enriched); TennisLive's statistics.
* B3, referee-free accuracy for every match: the accounting identities with the score (games = holds + opponent's breaks conceded, serve-game alternation, winner's points share, the definition tests).
* B4, corruption: Stage 0 rows contradicted by a complete recount and by at least one other independent source equal to the recount, with a unique whole-box replacement that passes Stage 0's checks. Listed as a candidate correction table.
* B5, the blend: a per-match consensus box (one source's whole box, chosen by agreement with the others), scored against a referee left out of its construction.

**Part C: results and scores.** Winner, set scores and status (completed, retired, walkover, default) in Stage 0 against tennis-data, TennisLive's listings, Flashscore, api-tennis, the official feeds, the WTA's site records and the ITF's live data; majority vote; Stage 0 rows contradicted by two or more independent sources.

**Part D: context.** Surface, indoor, level, round, best-of, tournament and match dates, seeds, start and end times: Stage 0 against tennis-data, the WTA calendar, Flashscore, TennisLive and the official feeds. The women's indoor order (the WTA calendar first, recommended on 9 Oct, awaiting the owner's confirmation) is checked here.

**Part E: birth dates.** Sackmann's and TML's player tables, the WTA API, the ATP profiles (handoff), Tennis Abstract bios; consensus and the rows where Stage 0's age disagrees.

**Part F: odds where Pinnacle is missing** (August 2025 on, the stand-in rows of the training data). BetOnline alone against blends with Betfair, Polymarket, tennis-data's PS column after August 2025, Bet365 and the books' average: log loss against results, walk-forward weights, matches before 29 Jul 2026 only.

**Part G: serve speed.** Per player-match, each source's first-serve average (Infosys key statistics, ManTennisData, SirGenkii, the daily feed, the Slam feeds) against the point-level mean of the same match; a consensus rule; how far it moves `spd_L` (data level only; no outcome read).

**Part H: synthesis.** Per field: is the model's source the most accurate on average; does a blend or consensus beat it; which rows are corrupt and how they would be fixed; the adoption kind and route. A model-level harm check (a candidate build and `compare.py`) only if a proposed repair is large enough to matter; it would be logged here before it runs.

**Rules held throughout:** read-only on every shared table (Stage 0, Stage 1, the dump, the decided tables); outputs only under `data/studies/source_reconciliation/`; no GPU; no git command that changes state; no outcome of a match from 29 Jul 2026 on.

**Execution:** Part A by the lead first. Then B (split WTA / ATP), C+D+E, F and G as parallel subagents with written briefs (appendix), each writing its own code under `src/eda/source_reconciliation/` and outputs under its own subfolder, and each finding the lead uses re-checked by the lead before it enters the README.

## 6. Judgment calls and deviations

1. **Scope: the model's raw fields only** (before any comparison). Fields no input reads are listed, not analysed. The other branch (every field of every dataset) would have added work without changing a model decision.
2. **Referees.** The tour's own point record, recounted, where it holds every point and fits the score; otherwise the identities with the score; otherwise a majority of independent families. Fixed before any comparison. Alternative: a majority of all copies, rejected because the copies are mostly of one origin.
3. **No averaging of box counts** (before any comparison), following the 6 Oct review's rule; the "blend" for counts is a vote that picks one source's whole box.
4. **The seal.** Outcome-based readings (odds only) stopped at matches before 29 Jul 2026, following earlier studies' proposed holdout (not decided).

## 8. Weak points

* **The assumption leaned on most:** that the tour's own point record is right where it disagrees with copies of its own published box. Both come from one scoring system; joint errors are invisible here. The volunteer charts are the only independent check and cover few matches (7 of the 122 S1 matches).
* **The WTA referee's first-serve split was tuned to the box** by the subagent, after seeing agreement. The O1 recommendation leaves out the 3 rows that rest on it; the WTA votes on first serves in are weak evidence either way.
* **The training seasons (2013–18) are the least checked:** no official point record for most tour matches; the site copies are not independent of Sackmann.
* **Classes drawn after seeing the listings** (O1's retirement exclusion; the context part's definitional classes). None used an outcome, but a different rule moves the counts.
* **The odds result rests on results already read** by earlier studies (the 2026 rows in particular) and on 4,340 matches; its men's slice is unresolved.
* **No model reading.** The README's case is data accuracy; a model-level harm would show only in the proposed candidate build.
* **Where a flaw would most likely hide:** in the linking of a source to Stage 0's match and player (a wrong link makes a disagreement that is not one). The readers were hand-checked (5–6 matches per reader, all passing), and the votes need the recount to fit Stage 0's score, which a wrong link rarely does.
* **A re-design would:** add the volunteer charts and the Hawk-Eye copy as independent referees at scale; fetch the ATP's per-match pages for 2013–20 to break the dependence on Sackmann; run the bundled candidate build with the harm check.
